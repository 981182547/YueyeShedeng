# SPOTLIGHT —— 越野射灯蓝牙控制器

安卓 App（Flutter）+ ESP32-C3 固件，通过 BLE 控制车上 8 个灯位的越野射灯。

配套固件在隔壁目录 `../smart_spotlight_ble/`，**旧固件 `../smart_spotlight_c3/` 没有动过**。

---

## 一、它能做什么

- **主页**：一张越野车实拍图，灯位光点叠在车上真实位置。点哪一组，哪组灯就亮。
- **单灯页**：8 个灯位一个一个独立开关。
- **底部模式条**：日行 / 白光 / 黄光 / 自动 / 爆闪。
- **掉电记忆**：设过的模式和灯位开关存在 ESP 的 NVS 里，下次上电自动恢复。没设置过默认白光。
- **实时同步**：车上的语音、光敏、雨滴传感器改了状态，ESP 会主动上报，手机界面立刻跟着变。

### 颜色是怎么来的

颜色**不是灯位的属性，是模式的属性**：

- 模式决定这一刻走**黄光通道**还是**白光通道**；
- 灯位掩码决定**哪几个灯位**亮。

两者互不干扰 —— 切模式不会改变开着哪些灯，开关灯位也不会改变颜色。

## 二、灯位与分组

8 个灯位，每个灯位有黄/白两路，共 16 路，正好占满一片 PCA9685。

| 灯位 ID | 位置 | 分组（界面编号） | 黄光通道 | 白光通道 |
|---|---|---|---|---|
| 0 | 前包围左 | **1** 前包围 | CH0 | CH8 |
| 1 | 前包围右 | **1** 前包围 | CH1 | CH9 |
| 2 | 立柱下左 | **2** 立柱下 | CH2 | CH10 |
| 3 | 立柱下右 | **2** 立柱下 | CH3 | CH11 |
| 4 | 立柱上左 | **3** 立柱上 | CH4 | CH12 |
| 5 | 立柱上右 | **3** 立柱上 | CH5 | CH13 |
| 6 | 车顶左 | **4** 车顶 | CH6 | CH14 |
| 7 | 车顶右 | **4** 车顶 | CH7 | CH15 |

- **前包围** = 保险杠两侧那对大圆灯
- **立柱下** = A 柱上「下面」那对圆灯
- **立柱上** = A 柱上「上面」那对圆灯
- **车顶** = 行李架上那对横条灯

车图上每个光点里标的数字就是它的组号，点它就开关整组。灯位编号在 App
和固件两边必须一致，协议就是靠这个数字对齐的。

## 三、颜色和模式是两个独立的维度

这是整个控制逻辑的核心，界面也是照这个分的：底部**上面一排选颜色，下面一排选模式**。

| 维度 | 取值 | 管什么 |
|---|---|---|
| **颜色** | 白光 / 黄光 | 灯发什么色 |
| **模式** | 常亮 / 日行 / 自动 / 爆闪 | 灯怎么个亮法 |
| **灯位** | 8 位掩码 | 哪几个灯位参与 |

三者互不干扰：**切模式不会把颜色弄丢，换颜色也不打断当前模式**，开关灯位不影响前两者。
日行、爆闪、常亮用的都是当前选中的那个颜色。

> 早期版本把「白光/黄光」和「日行/自动/爆闪」并排塞进同一排单选，
> 结果是选了黄光再点日行，颜色就被顶掉了 —— 因为日行当时写死是白光。现已拆开。

### 模式

| 编号 | 模式 | 行为 |
|---|---|---|
| 0 | 关灯 | 全部熄灭（颜色和灯位开关都保留） |
| 1 | 常亮 | 按设定亮度常亮，**只有这个模式亮度可调** |
| 2 | 日行 | 固定 10% 低亮度 |
| 3 | 自动 | 光敏定亮度（白天 20% / 夜间 100%） |
| 4 | 爆闪 | 三连闪 + 间隔，按节奏表 |

日行 / 自动 / 爆闪的亮度由固件按传感器和节奏表决定，所以 App 里的亮度滑条在这三个模式下是灰的。

### 唯一的例外：自动模式遇上下雨

自动模式下如果雨滴传感器触发，设备会**临时**把颜色切成黄光（穿透雨雾），雨停自动还原成你选的颜色。

这期间白/黄开关仍停在你选的那一档，下面会显示一行「检测到下雨，已临时转黄光」——
所以状态上报里分了两个字段：`userColor`（你选的）和 `activeColor`（这一刻真实输出的）。

## 四、蓝牙协议

封包格式：`[0xA5][OP][LEN_hi][LEN_lo][payload...]`

设备名 `OffRoad-Light`，UUID 用的是 Nordic UART 那一套：

- Service：`6e400001-b5a3-f393-e0a9-e50e24dcca9e`
- RX（App 写入）：`6e400002-...`
- TX（设备上报 Notify）：`6e400003-...`

**App → 设备**

| OP | 名称 | payload |
|---|---|---|
| 0x01 | 调试文本 | ASCII |
| 0x10 | 切模式 | `[mode]` |
| 0x11 | 设置全部灯位 | `[mask]` 8 位掩码 |
| 0x12 | 单灯开关 | `[lampId, on]` |
| 0x13 | 整组开关 | `[groupId, on]` |
| 0x14 | 亮度 | `[duty 0~100]` |
| 0x15 | 查询状态 | 空 |
| 0x16 | 切颜色 | `[color]` 0=白 1=黄，**只换颜色不动模式** |

**设备 → App（Notify）**

| OP | 名称 | payload |
|---|---|---|
| 0x20 | 状态上报 | `[mode, mask, bright, activeColor, night, rain, ver, userColor]` |

两个颜色字段分工不同：

- `userColor` — 用户**选定**的颜色，白/黄开关按它显示；
- `activeColor` — 这一刻**真实输出**的颜色，车图上的发光颜色按它渲染。

正常两者相等，只有自动模式遇雨时 `activeColor` 会被设备临时改成黄光。
这个值只能由设备告诉 App，不能自己推算。

> 解析时对 `userColor` 做了长度兼容：payload 只有 7 字节的旧固件，会拿 `activeColor` 顶上。

状态有变化就立刻上报，另外每 2 秒兜底报一次，防止丢包导致手机显示卡在旧状态。

## 五、怎么跑起来

### 1. 放车辆图片

把那张越野车图放进 `assets/images/`，文件名随便（`.png` / `.jpg` / `.jpeg` / `.webp`），
首选叫 `car.png`。图片宽高比是运行时读的，不用在代码里填。

### 2. 编译 APK

**本地那套 Flutter（3.29.2）太旧，装不上新版依赖，构建请走云端**：

把项目推到 GitHub，`.github/workflows/build.yml` 会自动构建，
在 Actions 页面底部 Artifacts 下载 `SPOTLIGHT-android`。也可以手动触发（Run workflow）。

### 3. 烧录固件

Arduino IDE 打开 `../smart_spotlight_ble/smart_spotlight_ble.ino`：

- 开发板：**ESP32C3 Dev Module**
- USB CDC On Boot：**Enabled**
- Partition Scheme：选带 OTA 或 **Huge APP** 的方案（BLE 协议栈较大，Default 可能装不下）
- 不需要装任何第三方库

### 4. 接线

```
IO4  -> PCA9685 SDA        IO5  -> PCA9685 SCL
IO7  -> 雨滴 DO (低=下雨)   IO8  -> 光敏 DO (低=白天, 高=黑夜)
IO2  <- CI1302 TX          IO3  -> CI1302 RX      (语音，可选)
```

---

## 六、灯位跟图对不上怎么办

灯位坐标是照着那张 Jeep 图量的，写在 `lib/models/lamp.dart` 的 `kLamps` 表里。
`x` / `y` 是相对坐标（0~1，相对图片左上角），换了别的车图就改这张表，其它代码都不用动。
